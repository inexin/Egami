Examples

// Decode H.264 and HEVC on the GPU wherever it can, with the software codecs for the rest: register the software
// codecs first, then the hardware ones. On a machine without a GPU the context stays as it was. At startup,
// MediaContext.SetDefault(context) makes it the context every reader uses.
MediaContext context = MediaContext.Default.WithH264().WithHevc().WithHardwareCodecs();
using (VideoReader reader = VideoReader.Open("clip.mp4", context: context))
{
    foreach (YuvVideoFrame frame in reader.ReadFrames())
    {
        using (frame)
        {
            count++; // the same samples as the software decoder gives, from whichever decoded it
        }
    }
}

// Encode on the GPU too: VideoWriter takes the codec the context holds for HEVC, which encodes on the GPU where it
// can code the options and in software where it cannot.
MediaContext both = MediaContext.Default.WithH264().WithHevc().WithHardwareCodecs(HardwareUse.All);
VideoCodec hevc = both.Codecs.First(c => c.CodecId == CodecIds.Hevc);
VideoWriterOptions fast = new() { Codec = hevc, FrameRate = new Rational(30, 1), Quality = 60 };

Methods

WithHardwareCodecs(MediaContext, HardwareUse)

Returns a copy of context that decodes H.264 and HEVC on the GPU, and encodes them there when use includes Encode, keeping the context's software codecs for whatever the GPU cannot do. Call it after WithH264 and WithHevc: it wraps the codecs registered for those ids, and a later registration replaces it. Without a GPU with Vulkan Video the context is returned as it is.

Remarks

Decoding moves to the software codec for tracks the hardware turns down up front (a bit depth or chroma format it does not decode), for scaled decoding, and for streams it refuses at their first picture: the packets sent until then are sent to the software decoder again. Frames are the same either way. Encoding, when asked for, moves to the software codec for options the hardware does not take (FirstPassStats) and when the GPU cannot code the profile, size, level or rate control; hardware output differs from the software encoders' and is bigger at the same quality, so encoding stays in software unless asked.
