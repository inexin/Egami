Class Mp3Format

MPEG audio files (.mp3, .mp2, .mp1, .mpa): MP3 and MP2 frames with their tags. The reader takes ID3v2.2, 2.3 and 2.4 tags (text frames into Tags, pictures as attachments with the front cover named cover.*, CHAP frames as chapters), ID3v1 and APEv2 tags at the end, and finds frames by three matching headers, so junk and false syncs are skipped. A Xing, Info or VBRI frame gives the frame count and duration, and its LAME tag the encoder delay and padding, so the audio is gapless: the first packet starts before zero and the last packet's duration stops at the source's end. Seeks are exact by default (FastSeek uses the Xing table instead). The writer stores an ID3v2.4 tag and the frames, with a Xing header and LAME-layout tag on a seekable stream, so MP3 can leave Matroska or MP4 without a re-encode.

Examples

// MP3 decodes to planar float; the LAME tag's delay and padding are trimmed, so the length is the source's exact length.
MediaInfo info = MediaFile.Probe("podcast.mp3");
Console.WriteLine($"{info.Tags["TITLE"]}: {info.Duration?.ToTimeSpan()}, {info.Chapters.Count} chapters, cover {info.Attachments[0].Name}");
using (AudioReader reader = AudioReader.Open("podcast.mp3"))
{
    reader.Seek(MediaTime.FromSeconds(0.15)); // exact: the next sample is the one at 150 ms
    Console.WriteLine($"{reader.Track.CodecId}, {reader.SampleRate} Hz, {reader.Layout.ChannelCount} channels");
}

// An MP3 track leaves Matroska without a re-encode; the .mp3 gets an ID3v2.4 tag and a Xing header.
MediaFile.Remux("episode.mka", "episode.mp3");

FastSeek

Gets whether readers seek by the Xing header's table (or VBRI's, or the bit rate) instead of exactly (V5.8 Design Q25). By default the first seek reads every frame header (4 bytes a frame) into an index, and seeks then land on the exact sample. Fast seeks read nothing first but land within about a percent of the duration, as FFmpeg and browsers do, and packet times after them are estimates. Register a format with this set through WithContainer(ContainerFormat).
