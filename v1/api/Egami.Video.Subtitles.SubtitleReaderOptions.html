Examples

// Files without a byte order mark that are not UTF-8 are read with the encoding you name, or else as Windows-1252, with a
// Subtitle.Encoding warning. Output is always UTF-8. Strict turns every repaired line into an exception.
MediaContext context = new() { Egami = EgamiContext.Default with { Diagnostics = d => log.Add($"{d.Id}: {d.Message}") } };
SubtitleDocument old = SubtitleDocument.Load("old.srt", context: context);
SubtitleDocument latin1 = SubtitleDocument.Load("old.srt", new SubtitleReaderOptions { Encoding = Encoding.Latin1 });
Console.WriteLine($"{old.Cues[0].PlainText} / {latin1.Cues[0].PlainText}");

try
{
    SubtitleDocument.Parse("1\n00:00:01.000 --> 00:00:02.000\nHi\n", options: new SubtitleReaderOptions { Strict = true });
}
catch (CorruptDataException e)
{
    Console.WriteLine(e.Message);
}

Properties

Encoding

Gets the encoding of files that have no byte order mark and are not valid UTF-8, or null to read them as Windows-1252 and report Subtitle.Encoding. WebVTT is always UTF-8, as its spec says, unless this is set. Code pages beyond .NET's built-in ones need Encoding.RegisterProvider(CodePagesEncodingProvider.Instance) first.

public Encoding? Encoding { get; init; }

Strict

Gets whether a malformed file throws instead of being repaired. False by default: SRT with missing blank lines, . for , or missing numbers, and ASS with bad lines are read, and Subtitle.Repaired says what was fixed. WebVTT always follows the W3C parsing algorithm, which skips what it cannot read; strict reading throws there too.

public bool Strict { get; init; }
