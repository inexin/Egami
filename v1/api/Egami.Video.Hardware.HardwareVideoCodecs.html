Finds the hardware video codecs of the machine's GPUs. The first call asks the GPU driver through Vulkan Video and keeps the answer for the life of the process; it never throws, and on a machine without a usable GPU or driver it finds nothing.

Examples

// Ask once whether the GPU encodes H.264 in hardware. The answer comes from the GPU driver and is kept for the life of
// the process; on a machine without a GPU or driver it is false, never an exception.
bool canEncode = HardwareVideoCodecs.IsAvailable(CodecIds.Avc, HardwareDirection.Encode);
bool canDecodeHevc = HardwareVideoCodecs.IsAvailable(CodecIds.Hevc, HardwareDirection.Decode);
Console.WriteLine($"H.264 encode: {canEncode}, HEVC decode: {canDecodeHevc}");

Remarks

Hardware decoding and encoding go through the Vulkan loader the GPU driver installs (vulkan-1.dll on Windows, libvulkan.so.1 on Linux). Egami ships no native code. The driver needs Vulkan 1.3 and the VK_KHR_video_queue extensions; current NVIDIA, AMD and Intel drivers have them. Egami.Video's software codecs stay the default.

The probe lists H.264 (High to decode; High, Main and Baseline to encode) and HEVC (Main and Main 10), all in 4:2:0.

Properties

H264

Gets the hardware H.264 codec: its CreateEncoder(VideoEncoderOptions, MediaContext) encodes on the GPU through Vulkan Video, 8-bit 4:2:0 in the Constrained Baseline, Main and High profiles. Hand it frames as Egami's software encoder takes them, with the same VideoEncoderOptions and H264EncoderOptions: quality, quantizer, constant and variable bitrate, keyframe interval, B-frames and Annex B packets. Its CreateDecoder(VideoTrackInfo, VideoDecoderOptions?, MediaContext) decodes progressive 8-bit 4:2:0 streams on the GPU to the same samples as Egami's software decoder; add it to a context with WithCodec(VideoCodec) to have VideoReader use it.

Examples

// H.264 on the GPU, in MP4: the same options as Egami's software encoder. Effort picks the driver's quality level.
VideoWriterOptions options = new() { Codec = HardwareVideoCodecs.H264, FrameRate = new Rational(30, 1), Quality = 60 };
using (VideoWriter writer = VideoWriter.Create("duck-gpu.mp4", options))
{
    for (int i = 0; i < 30; i++)
    {
        using Raster<Rgb8> frame = duck.Derive(ops => ops.Crop(new Rect(i * 4, i * 2, 320, 240)));
        writer.WriteFrame(frame);
    }
}

// A stream at 2 Mbit/s with a keyframe every second.
VideoWriterOptions streaming = options with { RateControl = RateControlMode.ConstantBitrate, Bitrate = 2_000_000, KeyframeInterval = 30 };
// Decode H.264 on the GPU where there is one: the hardware codec takes the software codec's place in the context.
MediaContext context = MediaContext.Default.WithH264();
if (HardwareVideoCodecs.IsAvailable(CodecIds.Avc, HardwareDirection.Decode))
{
    context = context.WithCodec(HardwareVideoCodecs.H264);
}

using VideoReader reader = VideoReader.Open("duck-gpu.mp4", context: context);
foreach (YuvVideoFrame frame in reader.ReadFrames())
{
    using (frame)
    {
        count++; // frame.Planes holds the 8-bit 4:2:0 picture, the same samples Egami's software decoder gives
    }
}

Remarks

Effort picks the driver's quality level: from effort 4 (the default) its best, lower efforts its faster levels. Quality maps to the quantizer on the software encoder's scale (Quality 60 is QP 17), with I and B pictures spaced from P pictures as the driver prefers (2 finer and 2 coarser where it doesn't say). B-frames are off unless BFrames asks for them, since some GPUs predict B pictures from the earlier reference only and they then cost more than P pictures; they need Quality. Realtime tunes the driver for low latency. The driver writes the SPS and PPS from Egami's values: the level, the VUI with the frames' color and frame rate, and the entropy coder, which drivers may change.

Scene cuts do not start keyframes (keyframes come at KeyframeInterval and where ForceKeyframe asks), adaptive quantization and first-pass statistics are not used, and HDR SEI messages are not written (the track carries the HDR metadata). The output differs between GPUs and drivers. Creating an encoder throws HardwareVideoException when no GPU encodes H.264, and NotSupportedException when the GPU cannot code the size, level or rate control asked for.

The decoder reads the stream with Egami's own H.264 parser, keeps the decoded picture buffer, and has the GPU decode each picture and copy it back; frames come out in output order as YuvRaster<TSample> of bytes, cropped, with the color the software decoder gives. Field pictures, MBAFF frames, monochrome, 4:2:2 and streams above 8 bits throw UnsupportedFormatException when their first picture comes; CanDecode(TrackInfo) turns down tracks whose bit depth or chroma format says so up front.

UnavailableReason

Gets why GetDevices() found no device with hardware video, such as a missing Vulkan loader or a driver without Vulkan Video; null when a device was found.

public static string? UnavailableReason { get; }

Property Value

string

Examples

// List the GPUs and what their video hardware does: codec, profile, bit depth, size limits and, for encoders, the rate
// control modes and quality levels. UnavailableReason says why the list is empty.
IReadOnlyList<HardwareVideoDevice> devices = HardwareVideoCodecs.GetDevices();
if (devices.Count == 0)
{
    Console.WriteLine($"No hardware video: {HardwareVideoCodecs.UnavailableReason}");
}

foreach (HardwareVideoDevice device in devices)
{
    Console.WriteLine(device);
    foreach (HardwareVideoProfile profile in device.Profiles)
    {
        Console.WriteLine($"  {profile}");
    }
}
