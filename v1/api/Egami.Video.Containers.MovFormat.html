Class MovFormat

Namespace
Egami.Video.Containers
Assembly
Egami.Video.dll

QuickTime movies (Apple's QuickTime File Format): .mov and .qt files. Reading is Mp4Format's, so a .mov reads exactly as it does there. Writing makes a QuickTime movie rather than ISO MP4: the qt brand, QuickTime's handler, sound and video descriptions, and the uncompressed layouts editing applications use. Registered ahead of Mp4Format in Default, so a .mov output is QuickTime; Mp4Format chosen by name still writes MP4.

Examples

// A .mov output is a QuickTime movie: H.264, HEVC, Motion JPEG, AAC, ALAC, PCM and uncompressed video, with QuickTime's
// own sound and video descriptions. Tracks read from a .mov in any other codec, such as a timecode, go back unchanged.
MediaFile.Remux("camera.avi", "camera.mov");
MediaFile.Remux("phone.mov", "phone-copy.mov");

// moov after the media, straight to the file; ISO MP4 when named so.
MediaContext moovLast = MediaContext.Default.WithContainer(new MovFormat { MoovAtEnd = true });
MediaFile.Remux("camera.avi", "camera-end.mov", context: moovLast);
using (Stream source = File.OpenRead("camera.avi"))
using (Stream mp4 = File.Create("camera.mp4"))
{
    MediaFile.Remux(source, mp4, "MP4", leaveOpen: true);
}

// Uncompressed 8-bit 4:2:2 for editing applications, stored as 2vuy (10-bit 4:2:2 frames as v210).
VideoWriterOptions options = new() { Codec = RawVideoCodec.Instance, ChromaFormat = ChromaFormat.Yuv422, FrameRate = new Rational(25, 1) };
using (VideoWriter writer = VideoWriter.Create("duck.mov", options))
{
    writer.WriteFrame(duck);
}

// A codec QuickTime cannot hold is refused, and the message names the format to use instead.
try
{
    MediaFile.Remux("movie.webm", "movie.mov");
}
catch (NotSupportedException e)
{
    Console.WriteLine(e.Message);
}

MoovAtEnd

Gets whether writers put moov after the media. By default moov comes first, so the movie plays while it downloads: on a stream that can seek and read, the media is written in place and moved forward at the end, else it waits in a temporary file. With moov at the end the media goes straight to the output, which must be able to seek.

Methods

CreateMuxer(Stream, IReadOnlyList<TrackInfo>, MediaMetadata, MediaContext, bool)

Creates a muxer that writes a QuickTime movie: ftyp with the qt brand, moov, a wide atom and one mdat; QuickTime media and data handlers (mhlr and dhlr); sound descriptions of version 0, 1 or 2 (PCM as sowt, twos, raw, in24, in32, fl32, fl64 or lpcm; AAC, MP3 and ALAC with their setup in a wave atom) with a chan layout; video descriptions with colr (nclc), fiel, pasp and, for uncompressed video, clap. Holds H.264, HEVC, Motion JPEG (as jpeg, or as the mjpa, dmb1 or AVDJ a QuickTime track was read with), uncompressed 4:2:2 (2vuy from 8-bit and v210 from 10-bit packets) and RGB (raw), AAC, MP3, ALAC, PCM, mov_text (tx3g on a subtitle track), and tracks read from MP4 or QuickTime with any other codec, whose sample descriptions are written back byte for byte, as are those of uncompressed tracks read from QuickTime. Chapters, cover art, tags, rotation and edit lists are written as Mp4Format writes them. There is no fragmented QuickTime: on an output that cannot seek and read back, the media waits in a temporary file.
