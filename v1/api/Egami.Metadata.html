Namespace Egami.Metadata

Classes

ExifData

A parsed EXIF block (a TIFF structure, CIPA DC-008): the tags of IFD0, the EXIF, GPS and interoperability sub-IFDs and IFD1 with its thumbnail, with typed getters for the common ones. An unedited block writes back byte for byte; after an edit it is laid out again, keeping the maker note at its old offset when it fits, since maker notes often hold offsets of their own.

ExifEntry

One EXIF value: its tag, TIFF type and raw bytes, with accessors that read them as text, integers or fractions.

FormatDetails

Format-specific details the reader found, such as the original color type or palette. Each format derives its own.

FrameMetadata

Metadata that belongs to one frame.

IptcData

Parsed IPTC-IIM datasets (IPTC-IIM 4.2), as news agencies, stock libraries and Lightroom write them next to XMP, with typed getters for the common ones. Shaped like ExifData: an unedited block writes back byte for byte; after an edit it is rebuilt in record and dataset order, record 1 first, with the coded character set (1:90) set to UTF-8 whenever a value is not plain ASCII.

IptcEntry

One IPTC-IIM dataset as stored: its key and its bytes.

RasterMetadata

Metadata that belongs to the whole raster. It is kept apart from the pixels and survives operations unless an operation makes it wrong. Metadata problems never fail a load: broken blocks are kept as bytes and noted in Warnings.

TextEntry

A text entry, such as a PNG text chunk or a GIF comment.

XmpArray

An XMP array: items in order, each a simple value (string), an XmpStruct or another XmpArray, with a language for the items of a language alternative.

XmpData

A parsed XMP packet: its properties by namespace URI and local name, each a simple value, an XmpArray or an XmpStruct, with typed getters and setters for what apps ask for most (Dublin Core, XMP Basic, Photoshop and TIFF properties). An unedited packet writes back byte for byte; an edited one is written as canonical RDF/XML with padding, keeping every property it does not know, qualifiers included.

XmpNamespaces

The namespace URIs of the XMP schemas apps use most.

XmpStruct

An XMP structure: named fields, each a simple value (string), an XmpArray or another XmpStruct, such as Iptc4xmpCore:CreatorContactInfo. XmpData holds its top-level properties the same way.

Structs

ExifFraction

A rational EXIF value, such as an exposure time of 1/250 or an aperture of 28/10.

ExifKey

An EXIF tag: its number and the IFD it lives in. The named keys cover the tags most programs read and write.

GeoPosition

A position from the GPS tags of an EXIF block.

IptcKey

An IPTC-IIM dataset: its record and dataset numbers, as "2:25" for keywords. The named keys cover the datasets news, stock and photo software read and write; any other pair works too.

Resolution

Physical pixel density.

XmpName

An XMP property name: a namespace URI and a local name, such as dc:title. Prefixes vary between files, so Egami never matches on them; XmpNamespaces holds the URIs of the common schemas.

ColorSpaceHint

What the raster's pixel values mean, as far as the file said.

ExifIfd

The image file directories (IFDs) an EXIF block holds its tags in.

ExifType

The TIFF data types EXIF values are stored as.

FrameBlend

How a frame is combined with what is already on the canvas.

FrameDisposal

What happens to a frame's area before the next frame is drawn.

ImageOrientation

How stored pixels must be turned to show the image upright: the EXIF Orientation tag (274). The value says which way the camera was held; AutoOrient applies it.

ResolutionUnit

The unit of a Resolution.

XmpArrayKind

The three kinds of XMP array.
