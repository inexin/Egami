Class Ffv1Codec

Namespace
Egami.Video.Codecs
Assembly

FFV1, the lossless video codec archives use (RFC 9043), as Matroska and AVI carry it: versions 0, 1 and 3, Golomb-Rice and the range coder with the default or a custom state table, YCbCr 4:2:0, 4:2:2, 4:4:4, 4:1:1, 4:1:0 and gray with or without alpha, and RGB with or without alpha, at 8 to 16 bits, every frame equal to FFmpeg's sample for sample. Frames come out as their own planes: 8-bit planes, or 16-bit planes holding 10, 12 or 16 bits, where depths 9, 11, 13, 14 and 15 sit in the next of those with their samples shifted up. RGB comes out as G, B and R planes tagged Identity. Version 2, which was experimental, and 4:4:0 streams are not decoded.

Remarks

FFV1 carries no color information, so the frame's color comes from the container (Color), or is BT.601 limited range when it says nothing. Broken data follows Errors and is reported through the Egami context's diagnostics as Ffv1.SliceCrc (a slice's CRC does not match), Ffv1.ConfigCrc (the configuration record's CRC does not match), Ffv1.CorruptFrame (a slice or frame cannot be read) or Ffv1.MissingReference (a non-keyframe with no keyframe before it). In Conceal mode a damaged slice shows the last good frame there.

Ffv1VerifyResult result = Ffv1Codec.Verify("master.mkv");
Console.WriteLine($"{result.Frames} frames, {result.Slices} slices checked: {(result.IsIntact ? "intact" : "damaged")}");
foreach (Ffv1VerifyError error in result.Errors)
{
    Console.WriteLine($"frame {error.Frame} at {error.Timestamp}, slice {error.Slice}: {error.Problem}");
}

Verify(string, MediaContext?, CancellationToken)

Checks an FFV1 file's fixity without decoding pictures: the configuration record's CRC, and in every frame of the first FFV1 track each slice's footer and CRC (RFC 9043 section 4.9). This is far faster than decoding, so archives can run it routinely. Versions 0 and 1, and version 3 written without slice CRCs, have no slice CRCs to check; the result says so in HasSliceCrcs.
