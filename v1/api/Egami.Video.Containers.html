Namespace Egami.Video.Containers

Classes

Ac3Format

Raw AC-3 and E-AC-3 (.ac3, .eac3, .ec3; ATSC A/52): sync frames back to back, with no container around them. AC-3 frames (Ac3) are read one per packet; E-AC-3 (EAc3) is passed through, an independent frame and the substreams that follow it per packet. Writing copies the packets out unchanged, so a track from MP4, Matroska, CAF or AVI can be extracted without decoding. Seeking builds a frame index in one pass.

AiffFormat

AIFF and AIFF-C (.aif, .aiff, .aifc; Apple's Audio Interchange File Format 1.3 and its AIFF-C draft): big-endian integer PCM, AIFF-C's little-endian (sowt), 24 and 32-bit (in24, in32), float (fl32, fl64) and G.711 (ulaw, alaw) samples. Other AIFF-C compressions (ima4, MACE, QDesign and so on) pass through undecoded with an "X_AIFC/" codec id. The NAME, AUTH, "(c) " and ANNO chunks and an ID3 chunk become Tags (ID3 pictures become attachments), MARK markers become chapters, and a CHAN chunk gives the channel layout. The writer stores integer PCM as AIFF and float as AIFF-C, the title, artist, copyright and comment in the text chunks, any other tag and cover art in an ID3 chunk, chapters as markers and the layout of more than two channels in a CHAN chunk. A non-seekable output is written through a temporary file, since AIFF's sizes come before the samples. Seeking is sample exact.

Av1AnnexBFormat

A raw AV1 stream in the length-delimited format of the AV1 specification's Annex B, as the AV1 conformance streams and aomenc --annexb=1 write it: each temporal unit, each frame unit in it and each OBU in that carries its length as leb128, and OBUs have no size field. Readers give each temporal unit as a packet of low-overhead OBUs with their size fields, the form every other container uses; writers turn such packets back, dropping the size fields and adding the lengths, with a temporal delimiter at the start of each unit. There are no timestamps: temporal unit n is at n frames of FrameRate. Reading a file and writing it back gives the same bytes. Not detected from the extension, which .obu files share: an Annex B file is recognized by its first temporal delimiter.

Av1ObuFormat

A raw AV1 stream of low-overhead OBUs (.obu; AV1 specification section 5.2), as aomenc writes with --obu and aomdec and dav1d read: each temporal unit starts with a temporal delimiter OBU, and every OBU has its size field. There is no header, index or timestamp, so temporal unit n is at n frames of FrameRate. Reading a file and writing it back gives the same bytes; the writer adds a temporal delimiter to a packet that has none. The track's size, bit depth, chroma format and av1C come from the first sequence header.

AviFormat

AVI, the RIFF-based container from Video for Windows, with the OpenDML extensions for files over 1 GB. Reads any AVI and writes Motion JPEG video with audio and other tracks copied through.

CafFormat

Apple's Core Audio Format (.caf): one audio track of PCM (integer or float, either byte order), G.711, ALAC, Opus, AAC, MP3, AC-3 or FLAC, with 64-bit chunk sizes, so no 4 GB limit. The packet table (pakt) cuts variable-size packets and gives the priming frames (CodecDelay) and the padding at the end; the magic cookie (kuki) becomes CodecPrivate; the info chunk becomes Tags; markers and regions, named from the strg chunk, become chapters; and a chan chunk gives the channel layout. Other formats pass through undecoded with an "X_CAF/" codec id. The writer streams PCM and G.711 (a data chunk sized -1 on a non-seekable output) and puts the packet table of other codecs after the samples, or before them through a temporary file when the output is not seekable. Seeking is sample exact for PCM and packet exact for the rest.

ContainerFormat

A container format: how to recognize it and how to open a demuxer or muxer for it. Register a new one with WithContainer(ContainerFormat).

FlacFormat

Native FLAC files (.flac): "fLaC", the metadata blocks and the frames. STREAMINFO gives the track; Vorbis comments become Tags (a WAVEFORMATEXTENSIBLE_CHANNEL_MASK comment the track's layout) and pictures become attachments, the front cover named cover.*. Frames are found by their sync code, header CRC-8 and footer CRC-16, so each packet is one whole frame; seeking uses the seek table, or one pass over the frames when there is none. The writer stores STREAMINFO, tags, cover art and padding; on a seekable stream it fills in the frame sizes, total samples and MD5 at the end and turns part of the padding into a seek table with a point every 10 seconds.

IvfFormat

IVF (.ivf): the bare frame container libvpx's tools and the VP8, VP9 and AV1 test vectors use. A 32-byte file header (FourCC, size, time base, frame count) and a 12-byte header per frame (size, timestamp), with no index. Reads and writes VP8 (VP80), VP9 (VP90) and AV1 (AV01) tracks; seeking scans the frame headers once. Reading a file and writing it back gives the same bytes.

MatroskaFormat

Matroska (RFC 9559) and its WebM subset. Both instances read either; they differ in the DocType and extension a muxer writes: Instance writes Matroska (.mkv), WebM writes WebM (.webm).

Mp3Format

MPEG audio files (.mp3, .mp2, .mp1, .mpa): MP3 and MP2 frames with their tags. The reader takes ID3v2.2, 2.3 and 2.4 tags (text frames into Tags, pictures as attachments with the front cover named cover.*, CHAP frames as chapters), ID3v1 and APEv2 tags at the end, and finds frames by three matching headers, so junk and false syncs are skipped. A Xing, Info or VBRI frame gives the frame count and duration, and its LAME tag the encoder delay and padding, so the audio is gapless: the first packet starts before zero and the last packet's duration stops at the source's end. Seeks are exact by default (FastSeek uses the Xing table instead). The writer stores an ID3v2.4 tag and the frames, with a Xing header and LAME-layout tag on a seekable stream, so MP3 can leave Matroska or MP4 without a re-encode.

Mp4Format

MP4 and QuickTime (ISO/IEC 14496-12 and 14496-14, and Apple's QuickTime File Format): .mp4, .m4v, .m4a and .mov files, flat or fragmented (CMAF, DASH segments). Reads every track: AV1, VP9, VP8, Motion JPEG, Opus, FLAC, PCM and mov_text map to their codec ids, and any other track (H.264, HEVC, AAC, timecode) is passed through so a remux keeps it. Edit lists are applied, the display matrix becomes Orientation, and tags, chapters and cover art are read.

Mp4FragmentOptions

How Mp4Format writes fragmented MP4 (ISO/IEC 14496-12 8.8, V4.3 Design Q1 and Q3): moov holds only the track setup, and the media follows as moof and mdat pairs, so nothing is written back and nothing waits in a temporary file. A fragment starts at the first video keyframe after Duration; audio-only files cut every Duration.

Mp4SegmentOptions

How Mp4SegmentWriter cuts segments and which playlists it writes.

Mp4SegmentWriter

Writes a file as segments for HLS and DASH (V4.3 Design Q6 and Q7): for each track a CMAF init segment (ftyp and moov) and numbered media segments (styp, sidx, moof and mdat), cut at the first video keyframe after SegmentDuration so every segment starts with one, plus an HLS multivariant playlist with a media playlist a track and a static DASH MPD. Each segment, read after its track's init segment, is valid fragmented MP4. A track is named after its kind and number: video1-init.mp4, video1-00001.m4s, video1.m3u8; the playlists are master.m3u8 and manifest.mpd. Holds the audio and video codecs Mp4Format writes, one rendition: bitrate ladders, live playlists and encryption are not written (Q8, Q9).

OggFormat

Ogg (.ogg, .opus, .oga), RFC 3533, with the Opus (RFC 7845), Vorbis and FLAC mappings. Pages are CRC-checked and packets rebuilt across them; timestamps come from granule positions, with Opus's pre-skip as the track's codec delay and the last page's granule position trimming the end. Seeking uses an index of granule positions built in one pass over the page headers on open. Chained files (one stream after another, as internet radio dumps are) read as one track when the codec settings stay the same, each link's TITLE a chapter; a link that changes them ends the track with an "ogg-chained-stream" warning. The writer stores Opus, Vorbis and FLAC with tags, so a WebM's Opus track remuxes to .opus without decoding.

RawVideo

Headerless raw video ("rawvideo"): frames of one uncompressed layout back to back, as FFmpeg's -f rawvideo reads and writes them. Nothing in the file says the size or layout, so the caller gives them as a track.

WavFormat

WAV (.wav): RIFF WAVE with integer or float PCM, WAVE_FORMAT_EXTENSIBLE (channel mask and valid bits) and the compressed formats AVI also names, plus RF64 and BW64 for files over 4 GB (Instance) and Sony Wave64 (.w64, Wave64). Streamed files whose sizes were never filled in (0 or 0xFFFFFFFF) are read to the end. LIST/INFO and id3 tags become Tags, and cue points with their labels become chapters. The writer stores PCM and float, INFO tags and chapters as cue points, and turns a WAV file into RF64 by itself when the data passes 4 GB, as EBU Tech 3306 says (a JUNK chunk reserved after the header becomes the ds64 chunk). Seeking is sample exact.

Y4mFormat

YUV4MPEG2 (.y4m): uncompressed planar YUV frames behind a one-line text header, the common exchange format of video tools and codec test suites. Reads 4:2:0, 4:2:2, 4:4:4 and gray at 8, 10 and 12 bits, and 4:4:4 with alpha; writes the same. Reading a file and writing it back gives the same bytes.

Interfaces

IDemuxer

Reads a container's tracks and packets. Packets come in file order, interleaved across tracks.

IMuxer

Writes packets into a container. Packets should come in timestamp order across tracks, as a demuxer returns them. Dispose() finishes the file if Finish() was not called.
