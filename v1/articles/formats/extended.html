Extended formats

Egami.Formats.Extended reads and writes image formats that most apps never meet but some still need: PCX, SGI, Sun raster, XBM, XPM, WBMP, Farbfeld and DDS textures. They are plugins on core Egami's public format API, the one your own format uses, so they load, probe, stream and save as the core formats do, inside the same safety limits. The package depends on core Egami only and ships with every Egami release.

Registering the formats

Nothing registers them on their own. WithExtendedFormats(), an extension method in ExtendedContextExtensions, returns a context with every stable format of the package, detected after core Egami's own; pass it to the calls, or make it the default once at startup with EgamiContext.SetDefault(new EgamiContext().WithExtendedFormats()).

// Every stable format of Egami.Formats.Extended, once at startup before any other Egami call:
// EgamiContext.SetDefault(new EgamiContext().WithExtendedFormats());

// ...or in a context of its own.
EgamiContext context = EgamiContext.Default.WithExtendedFormats();
using Raster image = Raster.Load("duck.png", context);

// A raster saves to a path through the context it was loaded with, so the extension picks PCX.
image.Save("duck.pcx");
using Raster back = Raster.Load("duck.pcx", context);
string format = back.Metadata.FormatName!;               // "PCX"

Each format also has its own method and its own FormatInfo, for an app that wants only one:

// One format at a time: each has its own method and its own FormatInfo.
EgamiContext context = EgamiContext.Default.WithSgi().WithSunRaster();
using (FileStream output = File.Create("duck.sgi"))
{
    image.Save(output, SgiFormat.Info);
}

RasterInfo info = Raster.Probe("duck.sgi", context);
Console.WriteLine($"{info.Format.Name} {info.Width}×{info.Height} {info.Layout.ChannelOrder}");

The formats

Format FormatInfo Reads Writes
PCX PcxFormat 1, 2, 4 and 8-bit indexed, 1-bit EGA planes, 24-bit and 32-bit, run-length coded or not 8-bit gray with a gray palette, or 24-bit RGB, run-length coded
SGI SgiFormat 1 to 4 channels of 8 or 16 bits, plain or run-length coded the raster's channels and depth, run-length coded unless SgiWriterOptions.Rle is off
Sun raster SunRasterFormat 1, 8, 24 and 32 bits, with or without a colormap, plain or run-length coded 8-bit gray or 24-bit, run-length coded when SunRasterWriterOptions.Rle is set
XBM XbmFormat X11 files of bytes and X10 files of 16-bit words X11, black where gray is below half
XPM XpmFormat version 3, any number of characters a pixel, None, hex colors and X11 color names every color of the raster, None below half alpha
WBMP WbmpFormat type 0, extension headers skipped type 0, white where gray is at least half
Farbfeld FarbfeldFormat 16-bit RGBA 16-bit RGBA
DDS DdsFormat Legacy and DX10 headers, BC1 to BC7, every DXGI format DirectXTex reads; every surface and mip through DdsReaderOptions Uncompressed formats and BC1 to BC7 with mips, arrays and cube maps

SGI and Farbfeld keep 16-bit samples and alpha. PCX, Sun raster and WBMP have no alpha, XPM only on or off, and a save that loses something the raster has says so in the Warnings, as Egami's own writers do. The formats with a run-length option take it from their writer options:

// SGI codes its rows by default; Sun raster writes them plain unless asked.
using (FileStream sgi = File.Create("duck.rgb"))
{
    image.Save(sgi, SgiFormat.Info, new SgiWriterOptions { Rle = false });
}

using (FileStream sun = File.Create("duck.ras"))
{
    image.Save(sun, SunRasterFormat.Info, new SunRasterWriterOptions { Rle = true });
}

What a header says that the pixels do not is kept in RasterMetadata.FormatDetails: PcxDetails (version, planes, palette), SgiDetails (image name, channels, depth), SunRasterDetails (depth, colormap, coding), XbmDetails and XpmDetails (the C name and the cursor hotspot), and DdsDetails (DXGI format, mips, cube and array layout, alpha mode). The SGI, XBM and XPM writers take the name and hotspot back from them.

// What the header said that the pixels do not: PcxDetails, SgiDetails, SunRasterDetails, XbmDetails and XpmDetails.
using Raster image = Raster.Load("arrow.xbm", context);
if (image.Metadata.FormatDetails is XbmDetails xbm)
{
    Console.WriteLine($"{xbm.Name}, hotspot {xbm.Hotspot}");
}

// Writers take the name and hotspot back from the details.
image.Metadata.FormatDetails = new XbmDetails { Name = "pointer", Hotspot = new Point(0, 0) };
image.Save("pointer.xbm");

Streaming and damaged files

PCX, Sun raster, WBMP and Farbfeld decode their rows from the input as RasterDecoder asks for them; an 8-bit PCX first reads to its end, where its palette is. SGI stores each channel as its own plane of bottom-up rows, and XBM and XPM are C source, so those three read the file whole. DDS skips to the surface it reads and decodes it a row of 4 × 4 blocks at a time. A lenient read of a file that ends early keeps the rows it has and leaves the rest transparent black, with a RowsMissing warning such as Pcx.RowsMissing; a strict read throws CorruptDataException.

Formats in preview

The package also holds formats still in development, as previews. A preview is never part of WithExtendedFormats(): its own With<Format>() method and its FormatInfo carry .NET's [Experimental] attribute with a diagnostic id of its own, so a call to it does not compile until the app suppresses that id, which is the opt-in. A preview may change, change its output or be removed in any minor release; it becomes stable after an API review, comparison gates and fuzzing, and the attribute comes off.

The ids are EGAMIX and three digits, one per format, given out in order from EGAMIX001 and never reused. Suppress one in the project file (<NoWarn>$(NoWarn);EGAMIX001</NoWarn>) or around the call (#pragma warning disable EGAMIX001). There are no formats in preview in this release. The egami command reads and writes them only with --preview-formats.
