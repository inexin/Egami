Thumbnails for the web

// Decode at the smallest JPEG scale that still covers 400 × 400, turn it upright, fit it, and save at quality 80.
using Raster photo = Raster.Load("sideways.jpg", options: new ReaderOptions { MinimumSize = new Size(400, 400) });
photo.Apply(ops => ops.AutoOrient().Fit(400, 400, enlarge: false));
photo.Save("thumb.jpg", new JpegWriterOptions { Quality = 80, StripMetadata = true });

The JPEG decodes at 1/2, 1/4 or 1/8 scale, AutoOrient turns only the small result, and the metadata is left out of the file.

Safe handling of untrusted uploads

EgamiContext strict = EgamiContext.Default with
{
    Limits = SafetyLimits.Default with { MaxPixels = 25_000_000, MaxTotalBytes = 256L * 1024 * 1024 },
};

try
{
    // Read the header first: cheap, and it rejects what you do not want before any pixel memory is used.
    RasterInfo info = Raster.Probe(upload, strict);
    if (info.Width > 8000 || info.Height > 8000)
    {
        throw new InvalidDataException("Too large.");
    }

    using Raster image = Raster.Load(upload, strict, new ReaderOptions { Recovery = RecoveryMode.Strict });
    Console.WriteLine($"{info.Format.Name} {image.Width} × {image.Height}");
}
catch (UnsupportedFormatException)
{
    Console.WriteLine("Not an image format we accept.");
}
catch (LimitExceededException e)
{
    Console.WriteLine($"Over the {e.LimitName} limit.");
}
catch (CorruptDataException e)
{
    Console.WriteLine($"Damaged at byte {e.Offset}.");
}

See the security guide for every limit.

Log Egami's warnings with ILogger

// With Microsoft.Extensions.Logging: one line at startup sends every call's warnings to the app's log, with the id as
// a property to filter and count on. Egami itself has no logging dependency.
EgamiContext.SetDefault(new EgamiContext
{
    Diagnostics = d => logger.Log(d.Level.ToLogLevel(), "{Source} {Id} at {Offset}: {Message}", d.Source, d.Id, d.Offset, d.Message),
});

Set it once at startup; every call that passes no context then reports to the log. The diagnostics page lists every id.

Log Egami's warnings with Serilog

// With Serilog's static Log: the same one line, with Serilog's level names.
EgamiContext context = EgamiContext.Default with
{
    Diagnostics = d => log.Write(d.Level == DiagnosticLevel.Warning ? "Warning" : d.Level == DiagnosticLevel.Info ? "Information" : "Debug", "{Id}: {Message}", d.Id, d.Message),
};

Know which file a warning came from

// Per file: the handler's closure carries the path, so no correlation id is needed. Contexts are cheap records.
foreach (string path in Directory.EnumerateFiles(".", "*.png"))
{
    EgamiContext perFile = EgamiContext.Default with { Diagnostics = d => log.Add($"{path}: {d.Message}") };
    using Raster image = Raster.Load(path, perFile);
}

Reject damaged uploads

// Warnings as errors: a handler that throws fails the call with its exception, and nothing the call allocated is leaked.
EgamiContext strict = EgamiContext.Default with
{
    Diagnostics = d => throw new InvalidDataException($"{d.Id}: {d.Message}"),
};

try
{
    using Raster image = Raster.Load(SampleFiles.Damaged(), strict);
}
catch (InvalidDataException e)
{
    Console.WriteLine($"Rejected: {e.Message}");
}

A handler that throws turns every warning into an error; RecoveryMode.Strict does the same for damage alone, without a handler.

Use from ASP.NET Core

// In an ASP.NET Core endpoint: `upload` is IFormFile.OpenReadStream(), `response` is HttpResponse.Body.
EgamiContext limits = EgamiContext.Default with
{
    Limits = SafetyLimits.Default with { MaxPixels = 40_000_000, MaxTotalBytes = 512L * 1024 * 1024 },
};

using Raster image = await Raster.LoadAsync(upload, limits, new ReaderOptions { MinimumSize = new Size(256, 256) }, Ct);
image.Apply(ops => ops.AutoOrient().Cover(256, 256), Ct);
await image.SaveAsync(response, JpegFormat.Info, new JpegWriterOptions { Quality = 85, StripMetadata = true }, Ct);

Egami has no ASP.NET Core dependency: it reads and writes any Stream. The async calls read the upload into a pooled buffer, counted against MaxTotalBytes, so a slow client never holds a thread.

Batch convert a folder

// Convert a folder of images to QOI, a few at a time. Each image runs on one thread, so the files run side by side.
EgamiContext oneThread = EgamiContext.Default with { MaxParallelism = 1 };
Directory.CreateDirectory("out");
Parallel.ForEach(Directory.GetFiles("in"), new ParallelOptions { MaxDegreeOfParallelism = 4 }, path =>
{
    try
    {
        using Raster image = Raster.Load(path, oneThread);
        image.Save(Path.Combine("out", Path.GetFileNameWithoutExtension(path) + ".qoi"));
    }
    catch (EgamiException e)
    {
        Console.WriteLine($"{path}: {e.Message}");
    }
});

Convert images to WebP for the web

// Photos as lossy WebP, graphics with few colors as lossless: Probe reads only the header to tell them apart.
foreach (string path in new[] { "duck.png", "egret.png" })
{
    using Raster image = Raster.Load(path);
    bool photo = image.Width * image.Height > 100_000;
    image.Save(Path.ChangeExtension(path, ".webp"), photo
        ? new WebpWriterOptions { Quality = 80, Effort = 4 }
        : new WebpWriterOptions { Lossless = true, Effort = 6 });
}

Quality and Effort mean what cwebp's -q and -m mean; lossless keeps every pixel. See the WebP guide for the other options.

Turn an animated GIF into WebP

// A GIF (or APNG) becomes an animated WebP in one Load and one Save: frames, delays and loop count carry over. Each frame
// stores only what changed; lossless frames are exact, MixedFrames keeps whichever kind is smaller per frame.
using Raster gif = Raster.Load("pan.gif");
gif.Save("pan.webp", new WebpWriterOptions { Lossless = false, MixedFrames = true });

// Read back, every frame is the composed canvas, as with GIF and APNG.
using Raster<Rgba8> webp = Raster.Load<Rgba8>("pan.webp");
foreach (Frame<Rgba8> frame in webp.Frames)
{
    Console.WriteLine($"{frame.Metadata.Delay.TotalMilliseconds} ms, changed {frame.Metadata.Bounds}, blend {frame.Metadata.Blend}");
}

Make an animated GIF from frames

// Start from one picture and add frames: each Add copies the frame you pass.
using Raster<Rgba8> animation = Raster.Load<Rgba8>("duck.png");
animation.Apply(ops => ops.Fit(120, 120));
using Raster<Rgba8> next = animation.Derive(ops => ops.HueRotate(120));
using Raster<Rgba8> last = animation.Derive(ops => ops.HueRotate(240));
animation.Frames.Add(next.Frames[0]);
animation.Frames.Add(last.Frames[0]);
foreach (Frame<Rgba8> frame in animation.Frames)
{
    frame.Metadata.Delay = TimeSpan.FromMilliseconds(400);
}

animation.Metadata.LoopCount = 0;   // forever
animation.Save("hues.gif");

Show video frames

// A player converts every frame into the same raster: after the first frame, nothing is allocated.
using YuvRaster<byte> frame = YuvRaster.Create(1280, 720, ChromaFormat.Yuv420, YuvColor.Bt709Limited);

Make a favicon

// A favicon: 16, 32 and 48 resized from one raster. A raster that is not square is centred on transparency.
logo.Save("favicon.ico", new IcoWriterOptions { Sizes = IcoWriterOptions.FaviconSizes });

// Windows' set: 16 to 256, the 256 entry as PNG and the rest as 32-bit BMP, as Microsoft's guidance asks.
logo.Save("app.ico", new IcoWriterOptions { Sizes = IcoWriterOptions.WindowsSizes, Filter = Egami.Operations.ResampleFilter.Lanczos3 });

// Hand-drawn small sizes: each raster is written at its own size; the 48 comes from the largest raster.
using Raster<Rgba8> drawn16 = logo.Derive(ops => ops.Fit(16, 16));

FaviconSizes writes 16, 32 and 48; every browser and Windows read the file. See the ICO guide.

List a PSD's layers

// Layer records come as metadata, bottom to top as the file lists them; their pixels are not loaded.

foreach (PsdLayer layer in ((PsdDetails)image.Metadata.FormatDetails!).Layers)
{
    if (layer.Kind == PsdLayerKind.GroupEnd)

Clip a photo to a circle

// A round avatar: clip to a circle, draw the photo scaled to fill it, then ring it.

Cut a frame out of a shape

// A frame: one round rectangle cut out of another, kept as curves, so a PDF or SVG backend writes it exactly.
Path frame = Path.RoundRect(new RoundRect(new RectF(0, 0, 200, 140), 24))
    .Difference(Path.RoundRect(new RoundRect(new RectF(20, 20, 160, 100), 12)));

// Many shapes in one pass, applied left to right; overlaps and self-intersections removed; an area grown by 4 units.
Path dots = Path.Combine([Path.Circle(new Vector2(40, 40), 30), Path.Circle(new Vector2(80, 40), 30), Path.Circle(new Vector2(60, 75), 30)], PathOp.Union);
Path clean = Path.Star(new Vector2(50, 50), 45, 20, 5).Simplify();
Path halo = dots.Inflate(4, LineJoin.Round);

Animate a line drawing itself

// Frames of a signature drawing itself: each frame strokes a longer part of the path.
Path signature = Path.ParseSvg("M10 60 C30 10 50 110 70 60 S110 10 130 60 S170 110 190 40");
List<Raster<Rgba8>> frames = [];
for (int i = 1; i <= 24; i++)
{

    using (RasterCanvas<Rgba8> canvas = frame.CreateCanvas())
    {
        Stroke pen = new(3) { Cap = LineCap.Round, Effect = PathEffect.Trim(0, i / 24f) };

Blend a row in a custom operation

/// <summary>A custom step that screens a horizontal gradient over each row, blending with the Compositor.</summary>
public sealed class ScreenGradient : IRasterOperation
{
    public Size OutputSize(Size input) => input;

    public void Run<TPixel>(OperationInput<TPixel> input)
        where TPixel : unmanaged, IPixelType<TPixel>
    {
        int width = input.Destination.Width;
        TPixel[] gradient = new TPixel[width];
        for (int x = 0; x < width; x++)
        {
            gradient[x] = TPixel.FromRgba8(new Rgba8(255, 220, 160, (byte)(255 * x / Math.Max(1, width - 1))));
        }

        input.ForEachBand((start, end) =>
        {
            for (int y = start; y < end; y++)
            {
                input.Source.Row(y).CopyTo(input.Destination.Row(y));
                Compositor.Blend<TPixel>(BlendMode.Screen, gradient, input.Destination.Row(y));
            }
        });
    }
}

Compositor.Blend works on any pixel type, so one custom step serves every raster.

Searchable text in a PDF

// What a PDF writer needs to keep shaped text searchable: each glyph's cluster points back into the text. A glyph that
// stands for several characters (the "ffi" ligature) maps to all of them in ToUnicode; a cluster whose glyphs were
// reordered or merged (Indic, Arabic marks) goes in an ActualText span instead.
GlyphRun run = new Font(face, 11).Shape("office hours");
var toUnicode = new Dictionary<ushort, string>();
for (int i = 0; i < run.Count; i++)
{
    int start = run.Clusters[i];
    int end = i + 1 < run.Count ? run.Clusters[i + 1] : run.Text!.Length;
    if (end > start)
    {
        toUnicode.TryAdd(run.Glyphs[i], run.Text![start..end]);
    }
}

A GlyphRun from the shaper carries the text and a cluster per glyph, in visual order; that is all a PDF writer needs for ToUnicode and ActualText.

Text flowing across two columns

// One article flowed down two columns of a page: LineFlow hands out one line at a time at the width asked for, so the
// first column can be narrowed beside a picture and the rest carries on in the second. On Egap's PDF canvas the same
// calls write searchable text.
ParagraphStyle style = new() { DefaultStyle = new TextStyle { FontFamilies = [family], Size = 10 }, Align = TextAlign.Justify };

(float X, float Top, float Bottom)[] columns = [(40, 60, 300), (310, 60, 300)];
foreach ((float x, float top, float bottom) in columns)
{
    float y = top;
    while (!flow.IsComplete)
    {
        float width = x == 40 && y < 160 ? 150 : 245;      // beside a picture at the top of column one
        TextLine line = flow.NextLine(width)!;
        if (y + line.Height > bottom)
        {
            flow.Rewind(line.Start);                        // that line goes to the next column
            break;
        }

        foreach (LayoutRun run in line.Runs)
        {
            if (run.Glyphs is { Count: > 0 } glyphs)
            {
                page.DrawGlyphRun(glyphs, new System.Numerics.Vector2(x, y), new SolidPaint(Rgba8.Black));
            }
        }

        y += line.Height;
    }
}

Get the original JPEG back from a JPEG XL file

// A JPEG recompressed into JPEG XL loads as pixels like any other file, and gives its JPEG back byte for byte.
using Raster image = Raster.Load("recompressed.jxl");
if (((JxlDetails)image.Metadata.FormatDetails!).HasJpegReconstruction)
{
    JxlImage.ReconstructJpeg("recompressed.jxl", "original.jpg");
}

A JPEG recompressed losslessly into JPEG XL (cjxl does this by default for JPEG input) keeps a jbrd box, and JxlImage.ReconstructJpeg writes the original file from it, byte for byte. Loading such a file gives its pixels, as viewers show them.

Recompress a JPEG into JPEG XL without loss

// A JPEG becomes a JPEG XL file about a fifth smaller with the same pixels, and comes back byte for byte.
JxlImage.RecompressJpeg("duck.jpg", "duck.jxl");
JxlImage.ReconstructJpeg("duck.jxl", "duck-again.jpg");

The JPEG's own coefficients become the JPEG XL image, so nothing is decoded again or lost: the file loads to the pixels the JPEG gave, about a fifth smaller (as cjxl makes it, within a few bytes), and JxlImage.ReconstructJpeg writes the original back byte for byte. Baseline and progressive JPEGs with any Huffman tables, restart markers, ICC, Exif and XMP are taken; arithmetic-coded, lossless, hierarchical, 12-bit and CMYK JPEGs, and 4:1:1 sampling, are refused.

Save a lossless JPEG XL file

// Lossless JPEG XL, about the size cjxl -d 0 makes at the same effort (1 fastest to 7 smallest, 5 by default).
using Raster photo = Raster.Load("duck.png");
photo.Save("duck-lossless.jxl", new JxlWriterOptions { Lossless = true, Effort = 7 });

Every pixel comes back exactly, in the raster's own precision: 8 or 16-bit, half or single float, gray or RGB, with alpha when it is not opaque everywhere. The effort follows cjxl's: 1 is its fast path, 7 learns a context tree and tries palettes and color transforms, for files within a few bytes of cjxl's. The ICC profile (or an enumerated sRGB, linear or HDR space), EXIF, XMP and orientation are kept.

Save a lossy JPEG XL file

// Lossy JPEG XL at cjxl's default: quality 90, which is distance 1.0 (visually lossless).
using Raster photo = Raster.Load("duck.png");
photo.Save("duck-lossy.jxl", new JxlWriterOptions { Lossless = false });

// A distance as cjxl -d takes it instead of a quality, and more effort for a smaller file.
photo.Save("duck-small.jxl", new JxlWriterOptions { Lossless = false, Distance = 2.5f, Effort = 7 });

Lossy files are VarDCT in XYB, as cjxl writes them for PNG input, and come out within 5% of cjxl's size and Butteraugli score at the same settings (libjxl 0.12.0). Pick either a quality or a distance: Quality is cjxl's -q (90 by default, 100 lossless) and Distance its -d, where 1.0 is visually lossless and each step up gives a smaller file with more visible loss; a distance, when set, wins. Effort 1 to 7 is cjxl's -e: 6 adds the full block-size search and a per-block edge-preserving filter strength, 7 patches for repeated shapes such as text. Progressive and PhotonNoiseIso do what cjxl's -p and --photon_noise_iso do. Large images are coded in 2048-pixel chunks, as cjxl does, so memory stays bounded.

A JPEG source is better recompressed than re-encoded: Recompress a JPEG into JPEG XL without loss keeps its pixels exactly and the original file recoverable, where lossy encoding its decoded pixels loses detail a second time.

Keep alpha exact in a lossy JPEG XL file

// Alpha stays exact in lossy files by default, and fully transparent pixels keep their color.
using Raster<Rgba8> logo = Raster.Load<Rgba8>("duck.png");
logo.Save("logo.jxl", new JxlWriterOptions { Lossless = false, Quality = 85 });

// Smaller: alpha coded lossy too, and the color under transparent pixels left to the encoder (as cjxl does).
logo.Save("logo-small.jxl", new JxlWriterOptions { Lossless = false, AlphaDistance = 1, KeepTransparentColors = false });

Alpha is an extra channel coded apart from the color, exact by default, so cut-outs keep their edges (below distance 10; from there cjxl and Egami code the whole image at half size). AlphaDistance above 0 codes it lossy as cjxl's --alpha_distance does. Fully transparent pixels keep their color unless KeepTransparentColors is false, which lets the encoder replace it, as libjxl does by default, for a smaller file.

Decode a PDF's CCITT image

// An image XObject with /Filter /CCITTFaxDecode: DecodeParms keys not given keep PDF's defaults. The image's /Height
// stands in for a missing Rows, so the decoder stops where the image does.
CcittFaxParameters parameters = new() { K = k, EncodedByteAlign = aligned, Columns = columns, Rows = rows > 0 ? rows : height };
byte[] bits = CcittFax.Decode(data, parameters, out int decoded);

// The filter's samples: 0 black, 1 white. /Decode [1 0] inverts them, and an /ImageMask paints where a sample is 0.
bool invert = decode is [> 0.5, ..];
int rowBytes = (columns + 7) / 8;
using Raster<Gray8> image = Raster.Create<Gray8>(width, decoded);
for (int y = 0; y < decoded; y++)
{
    Span<Gray8> row = image.Row(y);
    for (int x = 0; x < Math.Min(width, columns); x++)
    {
        bool sample = ((bits[(y * rowBytes) + (x >> 3)] >> (7 - (x & 7))) & 1) != 0;
        row[x] = new Gray8(sample != invert ? (byte)255 : (byte)0);
    }
}

CcittFax.Decode gives what the CCITTFaxDecode filter gives, byte-aligned Group 4 included; the image's /Decode, /ImageMask and color space then apply as after any filter. To load the data straight to Gray8, use CcittFormat; see the CCITT guide.
