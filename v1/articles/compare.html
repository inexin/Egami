Egami and other .NET libraries

This page compares Egami with the five imaging libraries .NET developers most often weigh: ImageSharp, SkiaSharp, Magick.NET, NetVips and System.Drawing.Common. Egami is MIT-licensed, fully managed and runs anywhere .NET 10 runs, with formats and features that otherwise take several of these libraries. Another library is the better choice when you need .NET Framework, GPU drawing, ImageMagick's format list or libvips's low-memory pipeline; When another library fits better says which.

Facts about the other libraries come from their own NuGet pages, licence files and documentation, linked in Sources, as of 14 November 2026. A cell says "not documented" when we could not find the answer there; it does not mean the library lacks the feature. If something here is wrong or out of date, please open an issue.

Licence and deployment

  • Egami is MIT. It has no native files and no third-party dependencies, so one build runs on every OS and CPU .NET 10 supports, and publishes trimmed or as Native AOT. Optional packages keep patent-encumbered or niche formats out of the core: HEIC is in Egami.Heic, and camera RAW, DDS and other extra formats are in Egami.Formats.Extended.
  • ImageSharp is fully managed. Its Six Labors Split License gives Apache-2.0 terms to open source and source-available software, to transitive dependencies, to non-profits, and to for-profit users with less than USD 1 million annual gross revenue. Everyone else needs a paid Six Labors Commercial License, and the pricing page says a licence key is needed to build the software.
  • SkiaSharp is MIT and wraps Google's Skia. It ships a native library per platform; on Linux you pick a native assets package, with a NoDependencies variant for minimal containers.
  • Magick.NET is Apache-2.0 and wraps ImageMagick 7, with native files for each supported platform. PDF, PostScript and EPS need Ghostscript installed separately, and the docs say some formats are left out of the Linux and macOS builds where a licence or other issue prevents them.
  • NetVips is MIT, but the libvips library it needs is LGPL-2.1-or-later, and the NetVips.Native packages list LGPL-3.0-or-later. Check what the LGPL asks of you before you ship it.
  • System.Drawing.Common is MIT and wraps Windows GDI+. Since .NET 7 it runs on Windows only. Egami's System.Drawing drop-in offers the same API on every OS.

Speed

Egami aims to match or beat the other libraries on the same work. Benchmarks has 260 timed comparisons against ImageSharp 3.1.12, SkiaSharp and Magick.NET, with the dates of each run: Egami is faster in 234, within 5% in 16 and more than 5% slower in 10. Performance has the tips that keep your own code fast.

When another library fits better

  • You target .NET Framework or an older .NET. Egami needs .NET 10. SkiaSharp, Magick.NET, NetVips and System.Drawing.Common run on .NET Framework 4.6.2, and ImageSharp 4 on .NET 8.
  • You draw a UI on the GPU. SkiaSharp renders through OpenGL, Metal, Vulkan and Direct3D and is built into many .NET UI frameworks. Egami draws on the CPU.
  • You need ImageMagick's format list or its exact output. Magick.NET reads and writes over 100 formats, PDF and PostScript through Ghostscript, and matches the magick command's results.
  • You process very large images on little memory. libvips, through NetVips, runs whole pipelines a region at a time. Egami streams decoding and transcoding, but most of its operations work on a whole raster.
  • You have Windows code built on System.Drawing. It keeps working there. To run the same code on Linux or macOS, try Egami's System.Drawing drop-in and then migrate piece by piece.
