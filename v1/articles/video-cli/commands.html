egami-video command reference

Every egami-video command with its arguments and options, as egami-video <command> --help prints them. The options of all commands (-v, -vv, -q, --limit, --progress, --progress-format) are listed once, at the top. The egami-video command explains the conventions they share; run takes egami's steps.

Description:
  Inspect, remux, cut, join and convert video and audio files, and export and make frames, with Egami.Video, a fully managed video library.

Usage:
  egami-video [command] [options]

Options:
  -v, --verbose                  Write information to standard error.
  -vv, --debug                   Write debugging detail to standard error.
  -q, --quiet                    Write only errors to standard error: no warnings and no progress line.
  --limit <name=value,...>       Safety limits for decoded frames, such as pixels=100M,memory=2GB (names: pixels, width, height, frames, memory, metadata). EGAMI_LIMITS sets them too.
  --progress <file|->            Write progress to a file, or - for standard output: key=value lines as ffmpeg -progress writes them, or JSON with --progress-format json.
  --progress-format <keys|json>  How --progress writes: keys (the default, ffmpeg's key=value blocks) or json (one object per line).
  -?, -h, --help                 Show help and usage information
  --version                      Show version information

Commands:
  info <inputs>                 Show what media files hold: container, duration, tracks and codecs, tags, chapters and attachments; with options, packets and frames. Like ffprobe.
  remux <inputs>                Copy tracks into another container without decoding: change AVI to Matroska, pick tracks, keep tags, chapters and attachments.
  trim <inputs>                 Cut a part out of files: every track from --from up to --to, with timestamps starting at 0; subtitle cues shown across the cut are clipped to it. Without --smart or --reencode nothing is decoded and the cut starts at the video keyframe at or before --from, like ffmpeg -ss -to -c copy.
  concat <inputs>               Join clips with the same tracks and codecs into one file without decoding, one after another in the order given (globs sorted by name).
  segment <inputs>              Split files into parts without decoding, at video keyframes: -o names the parts with {part} (from 1), such as out-{part:000}.mkv; a folder takes {name}-{part:000}.{ext}.
  timestamps <inputs>           Change packet timestamps without decoding: shift tracks, re-time video to a constant frame rate, repair broken timestamps or start at 0. With --track, --shift, --rate and --fix change only those tracks; every track is written.
  extract <inputs>              Copy a track into its own file without decoding (VP8, VP9 and AV1 to IVF, PCM to WAV, FLAC to FLAC, Opus and Vorbis to Ogg, the rest to Matroska), or write attachments and cover art as files.
  embed <inputs>                Add tracks from other files, attachments and cover art to a file without decoding, and set track languages, names and defaults. Track numbers count the output's tracks from 1.
  metadata <inputs>             Write tags, chapters, track names and languages and attachment names as JSON, or copy a file with them changed from such a JSON or with --set, --remove and --chapter.
  subs                          Convert SRT, WebVTT and ASS files, shift and sync their timing, and copy subtitle tracks out of and into media files.
  frames <inputs>               Write video frames as images: every frame, one every few seconds, at given times, keyframes or a few evenly spaced.
  encode <inputs>               Make a clip from images, an image sequence or a Y4M stream, with Motion JPEG, VP8 or uncompressed video, and audio from another file.
  run <inputs-and-steps>        Run egami's steps over every frame of a video, separated by +, and encode it again: 'egami-video run in.mkv crop 0 60 1920 960 + resize 1280x + save out.mkv'. 'egami-video run --list' lists the steps; audio and subtitles are copied, and frames keep their times.
  thumbnail <inputs>            Write a representative frame of each video as an image: a typical frame of its opening, not a black or empty one, or the frame at --at.
  scenes <inputs>               Find the cuts between shots: list where each scene starts (frame, time and how sharp the cut is), and optionally write a frame of each.
  analyze <inputs>              Look for black, frozen, silent, cropped, interlaced and duplicate stretches, scene cuts, signal levels and loudness in one pass, as ffmpeg's detection filters do.
  waveform <inputs>             Draw the waveform of each file's audio as an image: the min to max outline of each column with the RMS level inside, as editors and podcast players show it.
  spectrum <inputs>             Draw the spectrogram of each file's audio as an image: frequency up, time across, level as color.
  generate <source> <file>      Write a test clip or sound: moving pattern with frame number and timecode, color bars, a solid color or a gradient, with or without a tone; or a sine, silence, noise or sweep on its own.
  sheet <inputs>                Make a contact sheet: a grid of evenly spaced frames, with their times and a title if asked.
  animate <inputs>              Make an animated GIF, WebP or PNG (APNG) from a stretch of video, at a frame rate and size of your choice.
  hash <inputs>                 Hash every decoded frame or packet of each track, in the layout of ffmpeg -f framemd5, to check that decoding matches.
  compare <reference> <inputs>  Measure PSNR and SSIM per plane between a reference clip and others, frame by frame in presentation order, as ffmpeg's psnr and ssim filters do.
  verify <inputs>               Check FFV1 files for damage without decoding: every slice's CRC and footer and the configuration CRC. Exit code 1 when a file is damaged.
  audio <inputs>                Decode audio to WAV, FLAC, Ogg FLAC, Opus, AIFF, CAF or ALAC in .m4a, or encode a video file's audio again while copying its video unchanged: resample, remix and change the sample format.
  join <inputs>                 Join clips of any size, frame rate and audio into one, fitted to one canvas, with an optional transition between them; everything is encoded again. For clips that already match, concat copies without decoding.
  fade <input>                  Fade a clip in from a colour and out to it, picture and sound together; like ffmpeg's fade and afade.
  overlay <main> <over>         Draw one clip over another, such as a logo or a keyed presenter, with an opacity and a time window; like ffmpeg's overlay (with chromakey and despill for --key).
  pip <main> <inset>            Show a second clip small in a corner of the first (picture-in-picture), with a time window and fades.
  stack <inputs>                Show clips side by side, one above the other, or in a grid; like ffmpeg's hstack, vstack and xstack.
  speed <input> <factor>        Play a clip faster or slower: the picture takes the nearest frames, and the sound keeps its pitch; like ffmpeg's setpts with atempo.
  reverse <input>               Play a clip backwards, picture and sound, holding only one keyframe interval at a time; like ffmpeg's reverse and areverse, which hold the whole clip.
  loop <input>                  Play a clip several times in a row; like ffmpeg's loop and aloop.
  freeze <input>                Hold one frame of a clip still for a while, with silence, then go on; --at end holds the last frame, like ffmpeg's tpad.
  slideshow <images>            Make a video of images shown one after another, with transitions and an optional pan and zoom; like ffmpeg's loop=1, zoompan and xfade, but with sub-pixel motion.
  stabilize <input>             Take the shake out of a clip in two passes: measure the camera's motion (corners tracked with Lucas-Kanade, a RANSAC fit), smooth its path with a Gaussian, and warp each frame onto it; like ffmpeg's vidstabdetect and vidstabtransform.
  edit <file>                   Render an edit file: clips on a track with transitions, layers over it and effects with time windows. Every other editing command writes one with --save-edit.
  formats                       List the containers and codecs egami-video reads and writes, like ffmpeg -formats and -codecs.
  ffmpeg <arguments>            Run an ffmpeg command line with egami-video: 'egami-video ffmpeg -i in.avi -c copy out.mkv'. --explain prints the native command instead. Takes -i, -f, -y, -n, -ss, -to, -t, -itsoffset, -framerate, -map, -c, -codec, -c:v, -c:a, -c:s, -vcodec, -acodec, -scodec, -an, -vn, -sn, -dn, -r, -s, -frames:v, -vframes, -q:v, -qscale:v, -ar, -ac, -sample_fmt, -metadata, -map_metadata, -map_chapters, -vf, -filter:v, -af, -filter:a, -lavfi, -filter_complex (psnr, ssim, showwavespic, showspectrumpic, and the editing filters), -loop 1 on an image, -segment_time, -segment_times, -update, -progress, -stats, -nostats, -stats_period, -hide_banner, -loglevel, -v, -nostdin, %d patterns and pipe:; filters scale, crop, pad, transpose, hflip, vflip, fps, thumbnail, select (scene), tile; to -f null the detection filters blackdetect, freezedetect, cropdetect, idet, signalstats, blurdetect, blockdetect, silencedetect, volumedetect, astats and ebur128; the audio filters volume, afade, atempo, adelay, apad, atrim, asetpts, highpass, lowpass, bandpass, bandreject, allpass, equalizer, bass, lowshelf, treble, highshelf, acompressor, agate, alimiter, loudnorm, silenceremove in -af; the editing filters fade, setpts (a constant factor), reverse, loop, tpad (clone), fps, scale, xfade, concat, overlay, hstack, vstack, xstack (grid), zoompan, chromakey, colorkey, despill, hflip and vflip (with enable), deshake, vidstabdetect and vidstabtransform; audio afade, acrossfade, amix, atempo, volume, areverse and aloop, with enable='between(t,a,b)', rendered as one edit; -f lavfi sources testsrc, testsrc2, smptebars, smptehdbars, color, sine, anullsrc and anoisesrc; anything else stops with exit code 2.
  ffprobe <arguments>           Run an ffprobe command line with egami-video: 'egami-video ffprobe -of json -show_streams in.mkv'. --explain prints the native command instead. Takes -i, -show_streams, -show_format, -show_packets, -show_frames, -show_chapters, -select_streams, -show_entries, -of, -print_format, -output_format (json, csv, compact, default, flat, xml), -v, -loglevel, -hide_banner, -pretty; anything else stops with exit code 2.
  mcp                           Serve egami-video's commands as tools to an AI assistant over the Model Context Protocol, on standard input and output. Tools read and write only inside the folders the assistant opened and those given with --allow, and never replace an input unless asked.

info

Description:
  Show what media files hold: container, duration, tracks and codecs, tags, chapters and attachments; with options, packets and frames. Like ffprobe.

Usage:
  egami-video info <inputs>... [options]

Arguments:
  <inputs>  Media files, globs (*, ?, **) expanded the same way in every shell, folders with --recursive, or - for standard input.

Options:
  -t, --track <track>                       Which tracks: v, a, s or d with an optional :index or :language (a:1, s:eng), or a track number as info shows it. Repeat it or separate with commas; all tracks by default.
  -an, --no-audio                           Leave out audio tracks.
  -sn, --no-subtitles                       Leave out subtitle tracks.
  -r, --recursive                           Take every media file in folders given as inputs, at any depth.
  -j, --jobs <count>                        How many files to work on at once; 0 (the default) for one per processor.
  --fail-fast                               Stop at the first file that fails.
  -a, --all                                 Also read every packet: packet and keyframe counts, start times, sizes and bit rates per track.
  --headers                                 Also show the codec headers of each track's first frame (profile, size, color and so on).
  --packets                                 List every packet: track, timestamps, duration, size and flags.
  --frames                                  Decode and list every frame: track, timestamp, duration, size or samples.
  -f, --format <text|json|csv|xml|ffprobe>  How to write: text (the default), json, csv (packet and frame lists), xml (the json fields), or ffprobe (JSON with ffprobe's field names).
  --json                                    Write JSON (schema 1); the same as --format json.
  --csv                                     Write CSV; the same as --format csv.

subs

Description:
  Convert SRT, WebVTT and ASS files, shift and sync their timing, and copy subtitle tracks out of and into media files.

Usage:
  egami-video subs [command] [options]

Options:

Commands:
  convert <inputs>  Write subtitle files in another format (SRT, WebVTT, ASS), optionally cut to a time range, sorted or with overlaps fixed. What the target cannot hold is reported once per kind.
  shift <inputs>    Move subtitle times by an offset, and scale them for a speed or frame rate change.
  sync <inputs>     Retime subtitles by sync points: one moves every cue by the same amount, two also fix a speed difference.
  extract <inputs>  Write a media file's text subtitle tracks as SRT, WebVTT or ASS files: each in its own format, or the one --format names.
  embed <inputs>    Add subtitle files to a media file as tracks, copying its other tracks without decoding. SRT, WebVTT and ASS stay as they are in Matroska; WebM takes WebVTT and MP4 mov_text or WebVTT, converted as needed.

subs convert

Description:
  Write subtitle files in another format (SRT, WebVTT, ASS), optionally cut to a time range, sorted or with overlaps fixed. What the target cannot hold is reported once per kind.

Usage:
  egami-video subs convert <inputs>... [options]

Arguments:
  <inputs>  SRT, WebVTT, ASS or SSA files, globs (*, ?, **) expanded the same way in every shell, media files with a subtitle track, or - for standard input.

Options:
  -o, --output <path>            Where to write: a file, a folder, a template with {name}, {ext}, {dir}, {index} and {format}, or - for standard output (with --format).
  -f, --format <srt|vtt|ass>     The subtitle format to write: srt, vtt or ass, when -o's extension does not say.
  --encoding <name>              Read files without a byte order mark that are not UTF-8 in this code page, such as windows-1250, instead of Windows-1252.
  --strict                       Fail on a malformed file instead of repairing it with a warning.
  --bom                          Start the written files with a UTF-8 byte order mark.
  --crlf                         End lines with CR LF, as Windows tools write them, instead of LF.
  -t, --track <track>            The subtitle track of a media file input: s:1, s:eng or a track number as info shows it; the first one by default.
  -j, --jobs <count>             How many files to work on at once; 0 (the default) for one per processor.
  --in-place                     Replace each input with its changed file when there is no -o, or allow -o to name an input.
  --fail-fast                    Stop at the first file that fails.
  --from <time>                  Keep only what shows from this time on; cues across it are cut there.
  --to <time>                    Keep only what shows before this time; cues across it are cut there.
  --rebase                       Move the cues so --from becomes 0, as trim does to a video.
  --sort                         Put the cues in time order.
  --fix-overlaps                 Sort, and end each cue when the next one on its layer starts, so lines never show at once by accident.

  --coder <range|range-default|golomb>  FFV1: range (the default, smallest), range-default (the default state table) or golomb (faster, 8 bits at most).
  --context <small|large>               FFV1: the context model, small or large; picked from --effort by default.
