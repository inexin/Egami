Diagnostics

Egami can tell an app what it recovered from, what it lost on purpose and what it decided on the caller's behalf, through one optional handler on EgamiContext. Egami has no logging dependency: the handler is a plain delegate, so one line sends the events to ILogger, Serilog or the console.

// With Microsoft.Extensions.Logging: one line at startup sends every call's warnings to the app's log, with the id as
// a property to filter and count on. Egami itself has no logging dependency.
EgamiContext.SetDefault(new EgamiContext
{
    Diagnostics = d => logger.Log(d.Level.ToLogLevel(), "{Source} {Id} at {Offset}: {Message}", d.Source, d.Id, d.Offset, d.Message),
});

The handler

EgamiContext.Diagnostics is an Action<EgamiDiagnostic>, null by default. With no handler, nothing is built and nothing is allocated. Each EgamiDiagnostic carries:

Member What it holds
Level Warning, Info or Debug, mapping onto the log levels Warning, Information and Debug
Source The part of Egami that found it: Png, Tiff, Exif, Limits and so on (the id up to its first dot)
Id A stable id such as Png.ChecksumMismatch, to filter and count on without parsing text
Message What happened and what Egami did, as a sentence
Offset The byte offset in the input, when known
Frame The frame or page index, when known

Ids are listed below and are never renamed or reused once shipped, like the public API.

  • Levels. EgamiContext.DiagnosticLevel is the lowest level delivered, Warning by default. Events below it are never even formatted.

    // Info and Debug events are off unless asked for; below the level they are never even formatted.
EgamiContext verbose = EgamiContext.Default with
{
    Diagnostics = d => seen.Add(d),
    DiagnosticLevel = DiagnosticLevel.Debug,
};

using Raster image = Raster.Load("duck.jpg", verbose, new ReaderOptions { MinimumSize = new Size(100, 100) });
foreach (EgamiDiagnostic d in seen)
{
    Console.WriteLine($"{d.Level,-7} {d.Id}: {d.Message}");
}

  • Threads. The handler runs inline, on whichever thread found the event, possibly on several decode threads at once, so it must be quick and thread-safe. Egami takes no lock around it.

  • When Warnings arrive. The Warnings a load raises arrive as the call ends, in the order of Metadata.Warnings, on the calling thread; a RasterDecoder session sends them when it is disposed. A reader that waits for more input can take a warning back and read it again, so nothing is sent until it is final. Info and Debug events arrive as they happen. A load that throws sends no Warnings: the exception says what went wrong.

  • Errors. An exception from the handler fails the call with that exception, which turns warnings into errors. Nothing the call allocated is leaked.

    // Warnings as errors: a handler that throws fails the call with its exception, and nothing the call allocated is leaked.
EgamiContext strict = EgamiContext.Default with
{
    Diagnostics = d => throw new InvalidDataException($"{d.Id}: {d.Message}"),
};

try
{
    using Raster image = Raster.Load(SampleFiles.Damaged(), strict);
}
catch (InvalidDataException e)
{
    Console.WriteLine($"Rejected: {e.Message}");
}

  • Repeats. One id is delivered at most 10 times per call, then once more as "The same problem came up N more times". Metadata.Warnings holds the same capped list, so the two always agree. A hostile file cannot flood a log.

  • Per file. Contexts are cheap records, so a context per file, whose handler's closure carries the path, scopes the events to that file.

    // Per file: the handler's closure carries the path, so no correlation id is needed. Contexts are cheap records.
foreach (string path in Directory.EnumerateFiles(".", "*.png"))
{
    EgamiContext perFile = EgamiContext.Default with { Diagnostics = d => log.Add($"{path}: {d.Message}") };
    using Raster image = Raster.Load(path, perFile);
}

Metadata.Warnings

Every Warning a load raises is also in RasterMetadata.Warnings, an IReadOnlyList<EgamiDiagnostic>, with or without a handler. Info and Debug events never are. Metadata parsed on first use (XMP, IPTC, ICC) adds its warnings then, and sends them to the handler of the context the raster was loaded with.

// Without a handler the same Warnings are in the metadata, each with its id.
using Raster image = Raster.Load(SampleFiles.Damaged());
foreach (EgamiDiagnostic warning in image.Metadata.Warnings)
{
    Console.WriteLine($"{warning.Id} at byte {warning.Offset}: {warning.Message}");
}

bool checksumsOnly = image.Metadata.Warnings.All(w => w.Id == "Png.ChecksumMismatch");

Reporting from your own code

A format plug-in notes a recovery with EgamiInput.Warn(raster, id, message), which lists it in Metadata.Warnings and sends it to the handler as Egami's own readers do; EgamiInput.Diagnostics takes its Info and Debug events. Code with no EgamiInput, such as a video demuxer, starts a DiagnosticReporter for the call with EgamiContext.StartDiagnostics(), which applies the same level filter and cap; disposing it sends the counts of capped ids. Use your own source name in ids (Avi.IndexRebuilt), never one of Egami's.

// A decoder outside Egami (a video demuxer, a format plug-in's own entry point) reports through the same handler, with the
// same level filter and the same cap of 10 per id per call. Dispose the reporter when the call ends.
using (DiagnosticReporter diagnostics = context.StartDiagnostics())
{
    if (diagnostics.IsEnabled(DiagnosticLevel.Warning))
    {
        diagnostics.Report(DiagnosticLevel.Warning, "Avi.IndexRebuilt", "The index was missing; it was rebuilt from the frames.", offset: 4096);
    }

    diagnostics.Report(DiagnosticLevel.Info, "Mjpeg.DhtInserted", "Frames have no Huffman tables; the standard ones were used.");
}

Logging libraries

ILogger takes the mapping in the first example. Serilog's static Log is the same one line:

// With Serilog's static Log: the same one line, with Serilog's level names.
EgamiContext context = EgamiContext.Default with
{
    Diagnostics = d => log.Write(d.Level == DiagnosticLevel.Warning ? "Warning" : d.Level == DiagnosticLevel.Info ? "Information" : "Debug", "{Id}: {Message}", d.Id, d.Message),
};

Memory leaks are reported by PixelMemoryUsage.LeakDetected instead, because they belong to a memory source rather than a call and are found on the finalizer thread after the call has ended; see Memory and threading.
